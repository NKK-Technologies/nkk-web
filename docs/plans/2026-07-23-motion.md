# NKK Tech Site — Motion Plan

Add a coherent motion layer to the completed marketing site on `feat/marketing-site`.
Concept: **"the missing piece falls into place."** One well-orchestrated hero load
sequence (the jigsaw assembles, the brand piece drops in and settles into its float),
then quiet, physical motion everywhere else — staggered scroll reveals, card lifts,
a slowly marching dashed socket, a springy success check. The site should feel alive
but engineered: this is a B2B trust brand, not a toy.

## Repo Context

Vite 7 + React 19 + TS + Tailwind v4. Current page: `src/App.tsx` renders Nav · Hero ·
Services · WhyUs · Process · QuoteSection · Footer. Design tokens in `@theme` in
`src/index.css`. Tests: vitest + Testing Library (`npm test`), plus `npm run build`
and `npm run lint` — all three must stay green in every task. The visual design is
frozen (pixel-perfect handoff) — motion may not change any resting-state layout,
color, or spacing. The design system's own timing tokens (from
`design_handoff_nkk_website/design-system/tokens/effects.css`) are the base:
ease `cubic-bezier(.2,.6,.2,1)`, fast 120ms, medium 200ms.

## Global Constraints

- **No new runtime dependencies.** Motion = CSS keyframes/transitions + one small
  `Reveal` component using `IntersectionObserver`. (Test-only devDeps unchanged.)
- **Resting state is sacred:** after all entrance/reveal animations complete, the
  rendered page must be pixel-identical to the current build (same layout, sizes,
  colors, shadows at rest). Hover states may add elevation/tint; they must return
  cleanly.
- **Motion tokens** (add to `src/index.css`; use everywhere — no ad-hoc curves):
  - `--ease-standard: cubic-bezier(.2,.6,.2,1)` (hovers, menu — from the DS)
  - `--ease-out-soft: cubic-bezier(.22,.61,.36,1)` (reveals, entrances)
  - `--ease-spring: cubic-bezier(.34,1.56,.64,1)` (pops: check, badges)
  - Durations: hover/menu 200ms; reveals 650ms; entrances 500–900ms
- **Reduced motion is first-class:** under `@media (prefers-reduced-motion: reduce)`
  every reveal/entrance renders in its final visible state with no transition, every
  loop (float, marching ants) stops, and the hero piece keeps its static ~7° tilt.
  Gate `scroll-behavior: smooth` behind `prefers-reduced-motion: no-preference`.
  Hover color/elevation transitions may remain.
- **Scroll reveals must never hide content from tools or tests:** reveal styling is
  opacity/transform only (element stays in the DOM and accessibility tree);
  `IntersectionObserver` fires once per element (unobserve after reveal); if
  `IntersectionObserver` is unavailable, elements render visible immediately.
- **Stagger rule:** sibling cards/items stagger 80ms apart (via `transition-delay`
  passed by the `Reveal` component — a genuinely dynamic value, so an inline
  `style={{ transitionDelay }}` is the one permitted inline style).
- **Signature-vs-restraint:** the hero owns the only elaborate sequence. Everything
  else is limited to: fade-up reveal, hover lift/tint, and the two small pops
  (step badges, success check). Do not add parallax, scroll-jacking, cursor effects,
  or text-splitting animations.
- **Verification for every task:** `npm run build`, `npm run lint`, `npm test` green
  before committing. Commit on `feat/marketing-site`.

## Task 1: Motion foundation — CSS system + Reveal component

**Files:** `src/index.css` (extend) · `src/components/ui/Reveal.tsx` (new) ·
`src/components/ui/Reveal.test.tsx` (new) · `src/test/setup.ts` (extend).

1. **`src/index.css` additions** (keep all existing rules; motion lives alongside):
   - The three easing tokens above as `@theme` vars (`--ease-standard`,
     `--ease-out-soft`, `--ease-spring`).
   - Change `html` rule: `scroll-behavior: smooth` only inside
     `@media (prefers-reduced-motion: no-preference)` (keep `scroll-padding-top`
     unconditional).
   - **Reveal classes** (plain CSS in `@layer components`):
     ```css
     .reveal { opacity: 0; transform: translateY(20px);
       transition: opacity 650ms var(--ease-out-soft), transform 650ms var(--ease-out-soft); }
     .reveal.is-visible { opacity: 1; transform: none; }
     ```
   - **Keyframes** (used by Tasks 2–3; define now):
     - `riseIn`: from `opacity:0; transform:translateY(24px)` to visible — for the
       hero load stagger (650ms ease-out-soft, `animation-fill-mode: both`).
     - `pieceAssemble`: from `opacity:0; transform:scale(.92)` to visible (500ms
       ease-out-soft, fill both) — jigsaw pieces.
     - `socketIn`: from `opacity:0` to `opacity:1` (500ms, fill both) — dashed outline.
     - `pieceDrop`: from `opacity:0; transform:rotate(12deg) translate(34px,-46px)`
       to `opacity:1; transform:rotate(7deg) translate(0,0)` (900ms ease-out-soft,
       fill backwards) — the floating brand piece's entrance.
     - `march`: to `stroke-dashoffset: -12` (from 0) — marching-ants loop for the
       dashed socket; used as `animation: march 2.5s linear infinite`.
     - `popIn`: `0% { opacity:0; transform:scale(.5) } 100% { opacity:1; transform:scale(1) }`
       (400ms ease-spring, fill both) — success check, step badges.
     - `shakeX`: `0%,100% {transform:none} 25% {transform:translateX(-3px)} 75% {transform:translateX(3px)}`
       (300ms, run twice) — form error line.
   - **Reduced-motion guard** (one block):
     ```css
     @media (prefers-reduced-motion: reduce) {
       .reveal { opacity: 1; transform: none; transition: none; }
       .motion-safe-anim { animation: none !important; }
     }
     ```
     Every element that gets a keyframe animation also carries `motion-safe-anim`
     (so one guard kills all entrances/loops; the existing hero float already has
     `motion-reduce:animate-none` — it should also get the static-tilt fix in Task 2).
2. **`src/components/ui/Reveal.tsx`:**
   - Props: `children`, `as?: keyof JSX.IntrinsicElements` (default `'div'`),
     `className?`, `delay?: number` (ms, default 0), plus spread rest.
   - Renders the element with `reveal` + `className`, `style={{ transitionDelay:
     delay ? `${delay}ms` : undefined }}`; on mount creates one IntersectionObserver
     (`threshold: 0.15`, `rootMargin: '0px 0px -40px 0px'`), adds `is-visible` when
     intersecting, then unobserves and disconnects. If `typeof IntersectionObserver
     === 'undefined'`, set `is-visible` immediately.
   - Implementation via a `useReveal()` hook in the same file returning
     `{ ref, visible }` — keeps the logic testable; no separate file needed.
3. **`src/test/setup.ts`:** add a minimal `IntersectionObserver` mock class
   (constructor stores callback; `observe`/`unobserve`/`disconnect` no-op; expose
   the instances on `globalThis.__io` so tests can fire callbacks manually).
4. **TDD `Reveal`** (`Reveal.test.tsx`): renders children without `is-visible`
   initially; firing the observer callback with `isIntersecting: true` adds
   `is-visible` and unobserves; `delay` sets `transition-delay` style; custom `as`
   renders that tag; missing IntersectionObserver → `is-visible` immediately
   (temporarily delete the global in that test).

**Verify & commit:** `feat: motion foundation — reveal system, keyframes, reduced-motion guards`

## Task 2: Hero signature sequence + Nav motion

**Files:** `src/components/Hero.tsx` (edit) · `src/components/Nav.tsx` (edit) ·
`src/components/Nav.test.tsx` (extend).

1. **Hero load sequence** (pure CSS `animation-delay` on mount — no JS; every
   animated node gets `motion-safe-anim`):
   - H1: `riseIn` delay 0 · sub-paragraph: delay 120ms · CTA row: delay 240ms.
   - Jigsaw SVG group: the three filled `<path>`s get `pieceAssemble` at delays
     200 / 320 / 440ms (`transform-origin: center`; `transform-box: fill-box` if
     needed for correct SVG origin). The dashed socket path: `socketIn` delay 600ms,
     and additionally the infinite `march` loop (chain: `socketIn 500ms
     var(--ease-out-soft) 600ms both, march 2.5s linear 1.1s infinite`).
   - Floating piece `<img>`: chain `pieceDrop 900ms var(--ease-out-soft) 700ms
     backwards` **then** the existing `heroPieceFloat 5s ease-in-out 1.6s infinite`
     (comma-chained animations; the float's 1.6s delay starts it as the drop ends —
     `pieceDrop` ends at rotate(7deg) translate(0,0) which IS the float loop's 0%
     frame, so the handoff is seamless). Replace the current single
     `animate-hero-float` utility with these chained animations via an arbitrary
     `animate-[...]` value or a small CSS class — either is fine, but keep it in one
     place.
   - **Reduced motion:** all of the above carry `motion-safe-anim`; additionally the
     piece keeps its tilt when animations are off — add `motion-reduce:rotate-[7deg]`
     (fixes the final-review backlog item).
2. **Nav scroll elevation:** in `Nav`, track `scrolled = window.scrollY > 8`
   (passive scroll listener, initialized on mount, cleaned up). When scrolled, add
   `shadow-[0_1px_2px_rgba(10,25,47,.06),0_4px_12px_rgba(10,25,47,.08)]` (the
   shadow-card values) to the sticky wrapper; transition `shadow` 200ms
   ease-standard. Resting state at top of page: exactly as today.
3. **Desktop nav link underline:** each desktop link becomes
   `relative` with an `after:` pseudo — `after:absolute after:left-0 after:-bottom-1
   after:h-[2px] after:w-full after:bg-brand after:origin-left after:scale-x-0
   hover:after:scale-x-100 after:transition-transform after:duration-200` (keep the
   existing color hover). No layout shift (pseudo is absolute).
4. **Mobile menu open/close animation:** wrap the panel in a grid container
   animating `grid-template-rows` `0fr → 1fr` (+ opacity 0→1), 250ms ease-standard,
   inner wrapper `overflow-hidden`. The panel must now stay mounted (animate closed
   rather than unmount) — **update `Nav.test.tsx` accordingly**: assert visibility
   via the container's data-state/class (e.g. `aria-hidden` on the closed panel +
   `inert` attribute so hidden links aren't tabbable) rather than absence from DOM.
   Menu still closes on every link/CTA tap; `aria-expanded` unchanged. Add
   `aria-controls` on the toggle pointing at the panel id (second backlog item).
5. Hero has no scroll reveal (it animates on load); Nav has none.

## Task 3: Scroll reveals + micro-interactions (sections, form, footer)

**Files:** `src/components/Services.tsx` · `src/components/WhyUs.tsx` ·
`src/components/Process.tsx` · `src/components/QuoteSection.tsx` ·
`src/components/Footer.tsx` (all edits) · `src/components/sections.test.tsx`
(extend lightly).

1. **Scroll reveals** (use `Reveal` from Task 1):
   - Each section: wrap the `SectionHeader` in `<Reveal>` (delay 0) and each card in
     `<Reveal delay={i * 80}>`.
   - **Transform-collision rule (binding):** `Reveal` animates `transform`, and the
     hover lift also animates `transform` — they must NEVER live on the same
     element (`.reveal.is-visible { transform:none }` vs `hover:-translate-y-1` is
     a specificity tie decided by source order — fragile). Therefore: `Reveal` is
     the **grid-item wrapper** carrying only `reveal` (+ delay); the existing card
     element moves inside it unchanged and keeps all its visual classes plus the
     new hover classes. Where cards must equalize heights in a grid row, add
     `h-full` to the inner card element.
   - QuoteSection: intro column and form card each wrapped (delays 0 / 120ms).
   - Footer: one `Reveal` around the whole upper grid (delay 0) — nothing per-link.
2. **Card hover lifts** (Services, Process — white cards): add `transition-[transform,box-shadow]
   duration-200 ease-[var(--ease-standard)] hover:-translate-y-1
   hover:shadow-[0_4px_8px_rgba(10,25,47,.1),0_12px_32px_rgba(10,25,47,.14)]`
   (the DS `--shadow-raised`). WhyUs translucent cards: same lift plus
   `hover:bg-[rgba(230,243,250,.1)] hover:border-[rgba(230,243,250,.22)]`
   (transition background/border too).
3. **Icon chips** (Services): card gets `group`; chip adds `transition-[transform,background-color]
   duration-200 group-hover:scale-[1.08] group-hover:bg-[#D2E9F7]` (blue-100 from
   the DS ramp).
4. **Step badges** (Process): when the card's `Reveal` becomes visible, badge plays
   `popIn` — implement with a descendant rule in index.css:
   `.reveal.is-visible .badge-pop { animation: popIn 400ms var(--ease-spring) 200ms both; }`
   plus `.badge-pop { opacity: 0 }` under `.reveal:not(.is-visible)` scoping (and
   visible-by-default under reduced motion via the existing guard — extend the
   reduced-motion block: `.badge-pop { opacity: 1 !important; animation: none !important }`).
5. **Form feedback:** success block's check circle gets `popIn` (`motion-safe-anim`);
   the error `<p>` gets `shakeX` (300ms, `animation-iteration-count: 2`,
   `motion-safe-anim`) — re-triggers on each failed submit (key the element on an
   error counter so React remounts it; simplest: `key={errorCount}`).
6. **Tests:** existing section tests must stay green (reveal keeps content in the
   DOM — assert that: extend `sections.test.tsx` with one test that a revealed-later
   card's text is queryable before any observer fires). QuoteSection tests unchanged
   (roles/copy untouched).
